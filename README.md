## 已实现

醒来 → 白兔掉落怀表 → 洞口传来断续旋律，爱丽丝无意识接出后半句 → 白兔惊退并跳洞 → 调查白兔留下的痕迹与同纹碎片 → 用怀表观察残影或直接探索找到树根后的小径 → 收齐碎片后停下拼合 → 洞口回应已修复的开头，暗示后续乐句 → 主动进入黑洞。

音乐拼合不会开启道路，也不是进入黑洞的前置条件。找到小径后可以直接进入；未完成的音乐进度会如实保留。碎片收齐且小径已找到时，在调查对白结束后自然打开乐谱，玩家可随时退出。

## 核心设定

- 全游戏只有一首待修复的大旋律；每章末尾拼合本章乐句，为同一首旋律补上一部分，结局才完整奏响。
- 怀表只用于序章的残影找路，不是后续章节的解谜工具。第一章入口已停用怀表。
- 序章的三枚碎片为“微光”“回声”“余韵”：前两枚散落在洞边，第三枚在调查树根后获得。
- 目前没有真实音频；用“静默 → 微光 → 回声 → 静默”的意象连接完成排序教学，没有节奏或辨音判定。
- WASD / 方向键：移动。
- 轻点 E：附近物品交互；对白中按 E、空格或 Enter 继续。
- 按住 E 超过 0.25 秒：调查洞边断掉的脚印后，在附近观察过去。白兔残影沿旧脚印绕向树根后，约 1.8 秒展示完整路线。
- 松开 E：回到现在；沿洞口下方绕到树根后，轻点 E 调查缝隙。
- M：查看音乐碎片与大旋律进度；拼合界面支持拖入指定槽位，也可点击碎片或按 1/2/3 放入。点选两个已填槽可换位，拖动已放入的碎片也可换位；右键槽位移除，后面的碎片向前补位。
- 退格撤回末尾，Delete 移除选中的槽位（未选中则移除末尾），Enter 验证，Esc 返回；P 试听当前排列，L 回听累计乐句。Tab/方向键和空格可用于按钮焦点操作。音频未上传时提供明确的静音占位说明。
- 退出乐谱后再次打开，会保留尚未完成的排列。缺少碎片、排序错误都不消耗碎片，可继续探索或重排。
- 在小径末端按 E：直接主动进入黑洞，无需完成音乐拼合。
- Esc：暂停 / 继续；R：从头重玩。

屏幕上方显示当前目标、怀表与时间状态，下方显示附近交互。小径从一开始就存在，怀表只揭示痕迹，不改变地形；仔细探索也能直接调查树根后的缝隙，无需先观察。洞口中心不可走入，需要绕外缘走到下行入口，再主动交互进入。失焦和暂停会清除长按与过去状态；观察教学在调查洞边后才出现。

## 实现边界

爱丽丝、白兔、对白立绘与纸质对话框已替换为用户提供的 PSD 素材；森林、怀表、树根、小径和黑洞仍由几何图形绘制。人物采用静态方向图，左侧镜像，尚无行走循环；白兔残影使用同一素材半透明显示。移动范围和洞口使用坐标约束，尚未搭建 TileMap 和物理碰撞。音乐和环境音暂以对白描述；第一章是入口占位，尚无章节玩法。探索流程仍由 Prologue.gd 管理；音乐拼合已拆为独立 Godot 场景、乐句资源与进度 Autoload。

素材位于 `assets/user_art/`，来源、图层、裁剪区域、尺寸、脚底锚点和原文件 SHA256 记录于 `manifest.json`。原 PSD 保持不动；`tools/import_user_art.py` 可使用 Pillow、numpy 与 psd-tools 重新导出。立绘由 `tools/extract_portraits.py` 单独提取：爱丽丝取自 `未命名作品(1).psd` 的透明图层，白兔取自原 PSD 的立绘组，保留原始透明边缘并清除孤立杂点，不再从重叠合成页切人物。输出保留原生像素尺寸，爱丽丝 851×1698，白兔 1116×2997。

对白中爱丽丝固定左侧红框区域、NPC 固定右侧红框区域；保留完整全身透明素材，等比放大，使对话框上方主要显示头部到腰部，下半身在对话框后遮挡，不拉伸、不裁掉耳尖，旁白隐藏立绘。两个人物按各自身体构造调整构图，白兔包含耳朵；每个人物的宽高始终使用同一缩放系数。角色采用最近邻显示，立绘与对话框采用线性过滤。独立森林预渲染小样也已使用同一套爱丽丝方向图。重新提取立绘需要 psd-tools 1.26（本次仅安装在 `output/asset-tools/`，Godot 运行不需要 Python 或该库）。

修复进度可跨场景保留，但只在本次运行中有效，退出游戏后不会存档；R 会重置碎片及大旋律进度。没有预先假设全游戏的章节数量。

## 文件

- scenes/prologue/Prologue.tscn：主场景。
- scenes/prologue/Prologue.gd：绘制、移动、交互、对白、流程与过去观察。
- scenes/music/MelodyPuzzle.tscn / MelodyPuzzle.gd：可在 Godot 中编辑的独立拼合界面，负责排序、撤回、验证和试听。
- scenes/music/MelodyTile.gd：碎片与槽位的 Godot 原生拖放及右键交互。
- data/music/prologue_phrase.tres：序章乐句数据；可在 Inspector 修改碎片名称、视觉线索与正确顺序。
- scripts/music/MelodyPhrase.gd：供后续章节复用的乐句资源格式。
- scripts/music/MelodyProgress.gd：跨场景收集、章节乐句累计和重复完成保护。
- tests/prologue_flow.gd：Godot 无窗口流程回归。
- validate_project.py：已有离线结构校验工具。

## 后续上传音频

将音频文件加入工程，在 Godot 中选择 `data/music/prologue_phrase.tres`，把 `fragment_audio` 数组设为 3 项，按 `fragment_ids` 的顺序填入对应的 AudioStream（微光、回声、余韵）。界面已提供单片试听、当前排列试听和按章节顺序回听已修复乐句；缺少音频时会显示说明，不会播放虚构音效。

后续章节新建自己的 MelodyPhrase `.tres`，使用不同的 `phrase_id` 与递增的 `sequence_index`，配置本章碎片后即可复用 MelodyPuzzle 场景。未来关卡与章节数尚未实现，测试仅用临时资源验证多章累计逻辑。
