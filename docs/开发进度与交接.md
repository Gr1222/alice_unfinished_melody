## 2. 序章剧情流程（代码位置）

全部由 `scenes/chapters/prologue/PrologueDirector.gd` 用 `await` 顺序编排：

1. `run_intro()` → `run_opening()`：黑屏淡入 → 对话 `prologue_sister` → 变暗 + 音乐 `prologue_sleep` → 姐姐消失 → 变亮 → `prologue_wake`
2. `run_rabbit_pass()`：镜头右移 → 兔子在屏幕右侧出现（`prologue_rabbit_pass`）→ 跑出画面 → 镜头返回 → `prologue_alice_curious`
3. `start_exploration()`：任务 `QUEST_PRO_FOLLOW_RABBIT` + 移动教程；同时启动 `run_rabbit_roots()`
4. `setup_watch()` / `run_watch_pickup()`：靠近显示 E 教程 → 拾取 → 弹窗 → 解锁背包 → 背包教程
5. `run_rabbit_roots()`：（没怀表 → `prologue_no_watch`）→ 兔子独白 `prologue_rabbit_roots` → F 教程 → `prologue_rabbit_talk` → 跳洞 → 标记 `prologue_rabbit_talked` → `prologue_alice_study` → 任务 `QUEST_PRO_STUDY_WATCH` + 调律教程
6. `_on_tune_requested()` → `run_tuning_puzzle()`：解谜 → 保存排列 → 弹窗失去怀表 / 获得音符 A → 任务 `QUEST_PRO_APPROACH_HOLE`
7. `setup_hole()` / `enable_hole()` / `run_ending()`：解谜完成后洞口出现 `[F] 调查兔子洞` → `prologue_note_hole` → 音符飞出变大落在洞口 → 爱丽丝跳上 → 下沉 + 淡出 → `next_scene`（第一章占位）

系统之间只通过 autoload 与信号通信：`EventBus`（信号）、`GameState`（标记、背包、任务、解谜结果、操作锁）、`DialogueManager`、`Fader`、`Music`。
操作锁：任何系统用 `GameState.lock_control(原因)` / `unlock_control(原因)`，全部解锁后玩家才能移动。

### 3.1 换正式模型时要注意
- 代码只通过 `ActorModel` 的 `face_toward(方向)` / `set_motion(朝向, 是否在走, 是否在空中)` / `play_state("idle"|"walk"|"jump")` 控制外观，导演不知道里面是贴图还是模型
- 模型约定：原点在脚底、正面朝 +Z（不是的话用 `offset` / `yaw_degrees` 修正，不要改模型文件）
- 兔子洞：森林模型 `forest.glb` 里本身就有一个洞。正式洞模型加入后，如果出现两个洞，请建模从 `forest.glb` 里删掉旧洞（我们不改别人的模型）
- 爱丽丝的碰撞胶囊（`Alice3D.tscn` → `Collision`）与交互提示高度按新模型身高调整
- 如果正式模型需要更多动画（如对话手势），在 `models.json` 的 `animations` 加新状态，导演里调用 `play_state("新状态")`

## 4. 调律解谜：如何换成正式设计与音乐

现状：玩法逻辑完整并有测试（43 项）；**画面是程序占位样式，音频是程序生成的**。

### 4.1 只换音乐（不改代码）
1. 美术提供**两条等长、同速**的音频：钢琴主旋律、怀表声音（.ogg 或 .wav，WAV 必须是普通 PCM 头，见 `CLAUDE.md`）
2. 放进 `assets/audio/puzzle/`
3. 改 `data/puzzles/watch.json`：`melody`、`item_track` 填路径；`duration` 改成音频长度；`cuts` 改成切点（3~5 段，建议切在拍子上）；`placeholder.beat` 改成真实的每拍秒数（影响拍线网格）
4. 运行 `tests/tuning_puzzle.gd`（会检查切点是否合法）

### 4.2 换美术（大多不改代码）
- 界面元素都在 `scenes/puzzles/TuningPuzzle.tscn`（背景、托盘边框、音轨名、音量滑条、【重置】、【确认】），可直接换样式/贴图
- 音轨背景与钢琴音轨的绘制在 `TuningPuzzle.gd` 的 `_draw_decor()`；片段外观在 `PuzzleSegment.gd` 的 `_draw()`（可改为显示贴图）
- 开场/结束动画：`play_intro_animation()` / `play_outro_animation()`（目前是金色闪光），可替换为 AnimationPlayer 动画
- 布局尺寸常量见 `docs/调参指南.md` 第 5.5 节

### 4.3 如果正式设计改了玩法
以下文档中的规则目前已实现，改动时对照修改并更新测试：
- 进入后不能退出；先完整播放（不能操作）；下方音轨切成 3~5 段掉落（物理碰撞 + 界面抖动）
- 点击片段单独试听；拖到下方音轨按放入顺序排列；顺序自由（不要求与原曲相同）
- 【重置】在下方音轨右侧；全部放入后【确认】出现在音轨下方
- 确认后播放玩家的排列 → 结束动画 → 弹窗【失去道具 怀表】【获得道具 音符a】
- 解谜期间背景音乐淡出，结束后恢复进入前的曲目（`TuningPuzzle.run()` 内处理，所有解谜通用；时长 `MUSIC_FADE`）
- 排列保存在 `GameState.puzzle_results["watch"]`，**游戏后期要回放**：用 `TrackSequencer`，上方钢琴不变，下方按保存的片段编号播放

解谜是独立场景，导演只调用 `await puzzle.run()` 拿到排列结果。只要保留 `run()` 的返回值与 `config`（consume_item / reward_item），可以整体重写解谜场景而不影响序章流程。

### 换场景时的注意事项（第 9 步踩过的坑）
- 导演里所有“每帧等待”的循环都必须用 `next_frame()`，并在返回 false 时立刻 `return`。
  否则换场景时循环报错，后面的剧情会在被销毁的场景里继续执行（曾导致第一章残留 `dialogue` 操作锁、凭空弹出对话）。
- 操作锁、背包、任务、解谜结果都在 `GameState`（跨场景保存）：换场景前要释放自己加的锁；**不要** `GameState.reset()`。
