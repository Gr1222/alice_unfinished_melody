# 调参指南

本文档列出所有**可以调整而不需要改代码逻辑**的设置：在哪里、改什么、默认值是多少。
每次新增可调设置时都要更新本文档（见 `CLAUDE.md`）。

调整方式分三类：
- **Inspector**：在 Godot 编辑器中选中节点，在右侧 Inspector 面板修改，保存场景即可。
- **数据文件**：用文本编辑器修改 `data/` 下的 JSON / CSV 文件。
- **代码常量**：在脚本顶部的 `const` 中修改（需要懂一点 GDScript）。

## 3. 角色与兔子洞的外观（数据文件：`data/models.json`）

爱丽丝、兔子、姐姐、兔子洞都用同一个“外观槽”组件 `scripts/components/ActorModel.gd`。
**外观全部写在 `data/models.json`**，场景里只填 `Model Id`。换成正式模型不需要改代码，也不需要改场景。

| 外观槽 | 场景中的节点 | model_id |
|---|---|---|
| 爱丽丝 | `scenes/player/Alice3D.tscn` → `Model` | `alice` |
| 白兔 | `Prologue3D.tscn` → `Actors/WhiteRabbit` | `rabbit` |
| 姐姐 | `Prologue3D.tscn` → `Actors/Sister` | `sister` |
| 兔子洞 | `Prologue3D.tscn` → `Props/RabbitHole` | `rabbit_hole` |

### 3.1 换成正式模型（步骤）
1. 把模型（`.glb` 推荐，也可以是 `.tscn`）放进 `assets/models/`，例如 `assets/models/alice.glb`
2. 在 `data/models.json` 对应条目填 `"scene": "res://assets/models/alice.glb"`
3. 填动画名映射 `animations`：左边是游戏用的状态，右边是模型里的动画名（在 Godot 里双击 .glb 能看到，例如 `"walk": "Armature|Walk"`）
4. ⌘B 运行，按需调 `scale` / `offset` / `yaw_degrees`
5. 运行 `tests/actor_models.gd`（检查路径是否存在）

填了 `scene` 后占位贴图自动消失；路径写错时会退回占位并在输出里警告，不会崩溃。

### 3.2 每个条目的字段

| 字段 | 作用 |
|---|---|
| `scene` | 正式模型路径；空字符串 = 用占位 |
| `scale` | 模型缩放（导出单位不对时改，比如模型太大就改成 0.01） |
| `offset` | `[x, y, z]` 米：让模型脚底对齐地面（角色节点原点就是脚底） |
| `yaw_degrees` | 模型朝向修正（度）。游戏默认模型“正面朝 +Z”（glTF 标准）；如果角色走路时是倒着/侧着走，改成 180 或 ±90 |
| `animations` | `idle`（站着）、`walk`（走/跑）、`jump`（空中/兔子跳洞）→ 模型里的动画名。没有的动画可以删掉，游戏会保持当前动画 |
| `placeholder` | 没有模型时的占位：`animated_sprite`（爱丽丝行走图）、`directional_sprite`（正/侧/背三视图，兔子和姐姐用）、`disc`（地面深色圆盘，兔子洞占位；`radius` 半径米、`color` 颜色）、`sprite`（单张贴图）、`none`（不显示） |

**角色一律是 2D**（只有森林场景用 3D），所以占位贴图就是角色的正式外观；以后有 .glb 才需要填 `scene`。

`directional_sprite` 的字段：`front` / `side` / `back`（三张贴图路径）、`side_faces`（侧面原图朝向 `left` / `right`，向另一侧走时自动翻转）、`pixel_size`（大小：米/像素）、`offset`（`[x, y]` 额外像素偏移，一般 `[0, 0]`；贴图底边会自动对齐脚底，三张图高度不同也没关系）。朝向由 `face_toward` / `set_motion` 按镜头判断：朝向镜头 = 正面，背对镜头 = 背面，左右 = 侧面。

其他占位贴图的字段：`texture` / `frames`（贴图或 SpriteFrames）、`pixel_size`（大小）、`offset`（`[x, y]` 像素，让贴图底边对齐脚底，约等于“贴图高度的一半 − 脚下透明边”）、`faces`（原图朝向 left / right / front，用来自动翻转）、`tint`（染色，姐姐用）、`shaded`（是否受光照）。

当前：爱丽丝 = 行走图（`pixel_size` 0.0026、`offset` (0, 278)）；兔子 = `rabbit_{front,side,back}_v2.png`（0.005，侧面朝左，约 1.1 米高）；姐姐 = `sister_{front,side,back}.png`（0.0032，侧面朝右，约 1.7 米高）；兔子洞 = `none`（用森林模型里自带的洞）。

### 3.3 其他角色设置（Inspector）

| 节点 / 设置 | 默认值 | 作用 |
|---|---|---|
| 任意外观槽 → Turn Speed | 12 | 正式模型转身速度（弧度/秒）；占位贴图不用 |
| WhiteRabbit/Interactable | Action = talk、Prompt Height = 1.6、Range 半径 1.4 | 按 F 与兔子对话的范围与提示高度（自言自语后才启用） |
| RabbitHole/Interactable | Prompt Height = 1.4、Range 半径 1.6 | 按 F 调查兔子洞的范围 |

| Alice3D → Jump Speed | 4.8 | 起跳速度，越大跳得越高（当前约 0.9 米） |
| Alice3D → Gravity | 13.0 | 重力，越大落得越快 |
| Alice3D → Camera | （序章中已连接 Camera） | 让 WASD 相对镜头方向移动 |

**占位行走动画**：`scenes/player/alice_frames.tres`（从 `assets/user_art/alice_walk_sheet.png` 切出）。

## 4. 对话文本与流程（数据文件）

### 4.1 文本：`data/i18n/strings.csv`
- 列：`keys,zh,en`。改台词只改这里，**不要改 key**。
- 含逗号的文本要用英文双引号包起来。
- 新增中文字符后运行 `tests/dialogue_manager.gd`，它会检查字体能否显示所有字。

### 4.2 对话流程：`data/dialogue/prologue.json`
```json
"对话id": {
  "mode": "talk",        // talk = 对话（爱丽丝在左，对方在右）；monologue = 独白（说话者在左）
  "with": "rabbit",      // talk 时右侧的角色
  "lines": [
    {"speaker": "rabbit", "text": "DLG_PRO_RABBIT_TALK_01"},
    {"know": "rabbit"},  // 从这里起，该角色显示真名而不是 ？？？
    {"speaker": "", "text": "..."}  // speaker 为空 = 旁白（不显示名字，两侧立绘变暗）
  ]
}
```
- 可在单句上加 `"mode": "monologue"` 临时覆盖。
- 序章现有对话 id（按剧情顺序）：`prologue_sister`、`prologue_wake`、`prologue_rabbit_pass`、`prologue_alice_curious`、`prologue_rabbit_roots`、`prologue_rabbit_talk`、`prologue_alice_study`、`prologue_note_hole`；另有 `prologue_no_watch`（没拿怀表就走到兔子附近时）。

### 4.3 角色：`data/characters.json`

| 字段 | 作用 |
|---|---|
| name | 名字的字符串 key |
| portrait | 立绘路径；空字符串 = 暂无立绘（只显示名字） |
| faces | 立绘原图朝向：`left` / `right` / `front`。程序会自动翻转，使立绘始终面向屏幕中央 |
| waist | 腰部位于原图高度的比例（0~1）。值越小，显示的身体越少、立绘越大 |
| always_known | true = 一开始就知道名字；false = 显示 ？？？，直到对话中出现 `{"know": ...}` |

当前值：爱丽丝 waist 0.5（朝前）、姐姐 waist 0.8（朝前，`sister_portrait.png`）、兔子 waist 1.0（原图朝右，未知，`rabbit_portrait_v2.png`）。

## 5.5 调律解谜

### 数据：`data/puzzles/watch.json`（每个解谜一个文件，文件名 = 解谜 id）

| 字段 | 当前值 | 作用 |
|---|---|---|
| melody | 空 | 上方音轨（爱丽丝的钢琴主旋律）音频路径；**空 = 用程序生成的占位钢琴** |
| item_track | 空 | 下方音轨（怀表的声音）音频路径；**空 = 用程序生成的占位滴答声** |
| duration | 8.0 | 两条音轨的长度（秒）。**换成真实音频后改成音频的实际长度** |
| cuts | [0, 2, 3.5, 6, 8] | 下方音轨的切点（秒）：必须从 0 开始、到 duration 结束、递增，切成 **3~5 段**；段长可以不等。建议切在拍子上，保证每段听感完整 |
| melody_track_name / item_track_name | NAME_ALICE / ITEM_WATCH_NAME | 两条音轨左侧显示的名字（字符串 key） |
| consume_item / reward_item | watch / note_a | 解谜完成后失去 / 获得的道具 |
| placeholder.beat | 0.5 | 每拍秒数：决定拍线网格、片段上的拍点，以及占位音频的节奏 |
| placeholder.melody_notes | 16 个 MIDI 音 | 占位钢琴旋律（60 = 中央 C，0 = 休止），每拍一个音 |
| placeholder.bell_notes | 16 个 MIDI 音 | 占位滴答声中每拍的铃音音高（让每个片段听起来不同） |

> 换真实音频的步骤：把音频放进 `assets/audio/puzzle/`（.ogg / .wav）→ 填 `melody` 和 `item_track` → 改 `duration` 和 `cuts` → 运行 `tests/tuning_puzzle.gd` 检查切点是否合法。两条音轨应等长、同速。

## 8. 森林地图（数据文件：`data/forest.json`）

森林模型由 `ForestLevel` 在运行时按 `data/forest.json` 加载（场景里不再放模型节点）。**换新森林 = 把文件放进 `assets/`，改这个 JSON + 写一份 `layout.json`，不用改场景和代码。**

### 8.1 换森林的步骤
1. 把模型（.glb / .fbx，贴图放同目录）放进 `assets/`；用 `Godot --headless --path . --import` 导入
2. 改 `data/forest.json` 的 `model`；调 `scale` / `offset` / `yaw_degrees` 让模型**朝向正确、路面落在世界 y=0**（Godot 导入 .fbx 后常见是 Z 轴朝上，需要 `yaw_degrees` 旋转，并按地面高度设 `offset[1]`）
3. 新建 `layout.json`（可复制 `assets/new_forest/layout.json`），在 `forest.json` 的 `layout` 填路径；`route` 的点 = 玩家走的路径中线（世界坐标），第一个点是起点，最后一个点是兔子洞位置
4. 非 headless 运行 `Prologue3D.tscn` 或用截图脚本，沿路径走一遍：镜头不被遮挡、角色踩在地上、隐形墙不卡人
5. 改好后跑 `tests/project_structure.gd`、`player_movement.gd`

### 8.2 `data/forest.json`
| 字段 | 当前值 | 作用 |
|---|---|---|
| model | `new_background_original/…fbx`（Meshy 岛） | 森林模型路径 |
| scale | 1.5 | 模型整体缩放（让路更宽、角色相对模型更小） |
| offset | [0, -4.65, 0] | 模型位置偏移（米）；y 让路面落在 y=0 |
| yaw_degrees | -90 | 绕竖轴旋转；改这个后 `layout.json` 里的路线坐标也要跟着改 |
| layout | `res://assets/new_forest/layout.json` | 路线等布局数据 |
| floor_size | [48, 0.1, 44] | 地面碰撞盒（要盖住整张地图）；不填用 ForestLevel 的 Floor Size（34, 0.1, 28） |
| shader_folder | `""` | 旧森林（volume_forest）才需要：里面放 painted_ground / portal_interior 着色器，用来还原顶点色与洞内黑色；新模型留空即用模型自带材质 |
| environment | 见下 | 背景、环境光、阳光、雾（新森林是白天；旧森林是夜晚：`14232f` / `86939d` / 0.28 / `233844` / 0.009 / `bac8d0` / 0.72） |

`environment` 字段：`background_color`、`ambient_color`、`ambient_energy`、`fog_color`、`fog_density`、`sun_color`、`sun_energy`、`sun_rotation_degrees`（[x, y, z]）、`shadow_max_distance`。字段缺省时用夜晚森林的默认值。

### 8.3 `layout.json`
| 字段 | 必填 | 作用 |
|---|---|---|
| route | 是 | 路线点 `[x, y, z]`（y 恒为 0）。剧情按“距起点多少米”摆放怀表、兔子、洞口；起点 = 开场位置，终点 = 兔子洞 |
| path_half_width | 否（默认 1.15） | 路线两侧隐形墙离中线的距离（米），即可走路宽的一半 |
| blockers | 否 | 额外的碰撞方盒 `{position, size}`（如洞口两侧的树墩）；新森林为空列表；不写这个字段时沿用旧森林的洞口方盒 |
| jump_obstacle | 否 | 需要跳过的横木（旧森林有；新森林没有） |
| tree_proxies | 否 | 树木圆柱碰撞（旧森林有；新森林靠隐形墙） |
| sources | 否 | 蘑菇/符文的点光源（旧森林有；新森林没有） |

**注意**：新森林里路面有轻微起伏（树根附近约高 0.2–0.5 米），而路线与地面碰撞是平的（y=0）；路线终点特意设在树根隆起之前。兔子洞目前是 `models.json` 里的深色地面圆盘占位（`rabbit_hole` 的 `disc`，半径 `radius`、抬高 `offset[1]`），等建模给正式洞再换。

### 8.4 代码常量：`scripts/components/ForestLevel.gd`
| 常量 | 默认值 | 作用 |
|---|---|---|
| DEFAULT_PATH_HALF_WIDTH | 1.15 | `layout.json` 没写 `path_half_width` 时的路宽一半；新森林写了 1.6 |
| PATH_WALL_LAYER | 2 | 隐形墙所在的碰撞层 |
| LEGACY_BLOCKERS | 旧森林洞口两侧 3 个方盒 | `layout.json` 没有 `blockers` 字段时使用 |

PrologueDirector 里与地图有关的参数：`Opening Route Distance`（开场位置，距起点米数，默认 1.6）、`Watch Route Distance`（怀表位置，默认 8.0）、`Rabbit Roots From End`（树根兔子离终点的距离，默认 1.8）。**路线长度变了之后要检查这三项**（新森林路线约 22.6 米）。
